## What Is This Feature?

Monthly Budget Planning allows the user to:
- Select a year and month
- For each category, enter a planned amount (e.g., "I plan to spend $500 on groceries in June")
- If the plan already exists for that (year, month, category), it **updates** instead of creating a duplicate

This is called an **upsert** operation (update if exists, insert if not).

The budget plan is the **baseline** for reports. Without it, there is no target to compare actual spending against (variance = planned - actual).

---

## Key Concept: Request Flow

```
Frontend sends data
  → Route receives it at POST /api/budgets/upsert
    → Middleware validates input (year, month, categoryId, plannedAmount)
      → Controller extracts valid data and calls service
        → Service calls stored procedure in MySQL
          → Controller returns standardized JSON response to frontend
```

## Step 1: Add Validators to `src/middleware/validate-request.js`

Add these two functions **before** `module.exports`, then export them.

### Why these validators?
- `validatePositiveIntRange` — ensures year is 2000–2100 and month is 1–12
- `validatePositiveDecimal` — ensures planned amount is a positive number

```javascript
// Validates an integer field is within a min/max range
// source: 'body' (default) or 'query' depending on where the field comes from
function validatePositiveIntRange(fieldName, min, max, options) {
  const source = (options && options.source) || 'body';

  return (req) => {
    const container = req[source] || {};
    const value = container[fieldName];
    const parsed = Number(value);

    if (!Number.isInteger(parsed)) {
      return {
        field: fieldName,
        message: `${fieldName} must be an integer`
      };
    }

    if (parsed < min || parsed > max) {
      return {
        field: fieldName,
        message: `${fieldName} must be between ${min} and ${max}`
      };
    }

    container[fieldName] = parsed;
    return null;
  };
}

// Validates a decimal field is a positive number (> 0)
function validatePositiveDecimal(fieldName, options) {
  const source = (options && options.source) || 'body';

  return (req) => {
    const container = req[source] || {};
    const value = container[fieldName];
    const parsed = parseFloat(value);

    if (isNaN(parsed)) {
      return {
        field: fieldName,
        message: `${fieldName} must be a valid number`
      };
    }

    if (parsed <= 0) {
      return {
        field: fieldName,
        message: `${fieldName} must be greater than 0`
      };
    }

    container[fieldName] = parsed;
    return null;
  };
}
```

## Step 2: Replace `src/services/budgets.service.js`

The service layer is responsible for **calling the database stored procedures**. It never formats HTTP responses — that is the controller's job.

```javascript
const db = require('../config/db');

// Helper: gets the correct execute function from the db module
// The db module may expose execute() directly or through db.pool
function getExecute() {
  if (db && typeof db.execute === 'function') {
    return db.execute.bind(db);
  }
  if (db && db.pool && typeof db.pool.execute === 'function') {
    return db.pool.execute.bind(db.pool);
  }
  if (db && typeof db.query === 'function') {
    return db.query.bind(db);
  }
  throw new Error('Database executor is not configured');
}

// Helper: MySQL stored procedures return results in a wrapped array
// This unwraps that so we always get a flat array of rows
function unwrapProcedureRows(resultRows) {
  if (!Array.isArray(resultRows)) {
    return [];
  }
  if (Array.isArray(resultRows[0])) {
    return resultRows[0];
  }
  return resultRows;
}

// GET: fetch all budget plans for a given year and month
async function getBudgetPlanByMonth(year, month) {
  const execute = getExecute();
  const [rows] = await execute('CALL sp_get_budget_plan_by_month(?, ?)', [year, month]);
  return unwrapProcedureRows(rows);
}

// POST: create or update a budget plan for (year, month, categoryId)
// The stored procedure handles the insert-or-update logic
async function upsertBudgetPlan(year, month, categoryId, plannedAmount) {
  const execute = getExecute();
  const [rows] = await execute(
    'CALL sp_upsert_budget_plan(?, ?, ?, ?)',
    [year, month, categoryId, plannedAmount]
  );
  const data = unwrapProcedureRows(rows);
  return data[0] || null;
}

module.exports = {
  getBudgetPlanByMonth,
  upsertBudgetPlan
};
```

### What I Learned Here
- `?` placeholders in `execute()` prevent SQL injection — never concatenate values directly into SQL strings
- `async/await` is used because database calls take time (they are asynchronous)
- The service never knows about HTTP — it just returns data or throws an error

## Step 3: Replace `src/controllers/budgets.controller.js`

The controller is responsible for:
1. Extracting validated data from `req.body` or `req.query`
2. Calling the service
3. Sending a response using `sendSuccess()` or `sendError()`
4. Catching errors and mapping them to safe HTTP status codes

```javascript
const { sendSuccess, sendError } = require('../utils/api-response');
const budgetsService = require('../services/budgets.service');

// Maps database/service errors to safe, user-friendly messages
// This prevents raw database error text from reaching the frontend
function mapServiceError(err) {
  const rawMessage = err && err.message ? err.message : 'Request failed';
  const message = String(rawMessage);
  const lowered = message.toLowerCase();

  if (err && (err.code === 'ER_DUP_ENTRY' || lowered.includes('duplicate'))) {
    return { statusCode: 409, message: 'Budget plan already exists for this month and category' };
  }

  if (lowered.includes('not found') || lowered.includes('foreign key')) {
    return { statusCode: 404, message: 'Category not found' };
  }

  // MySQL SIGNAL SQLSTATE — custom errors thrown from stored procedures
  if (err && (err.sqlState === '45000' || err.code === 'ER_SIGNAL_EXCEPTION')) {
    return { statusCode: 409, message: message };
  }

  return { statusCode: 500, message: 'Internal server error' };
}

// GET /api/budgets?year=2025&month=6
async function getBudgetPlanByMonth(req, res) {
  try {
    const { year, month } = req.query;
    const plans = await budgetsService.getBudgetPlanByMonth(year, month);
    return sendSuccess(res, plans, 'Budget plans retrieved successfully', 200);
  } catch (err) {
    const mapped = mapServiceError(err);
    return sendError(res, mapped.message, null, mapped.statusCode);
  }
}

// POST /api/budgets/upsert
// Request body: { year, month, categoryId, plannedAmount }
async function upsertBudgetPlan(req, res) {
  try {
    const { year, month, categoryId, plannedAmount } = req.body;
    const result = await budgetsService.upsertBudgetPlan(year, month, categoryId, plannedAmount);
    return sendSuccess(res, result, 'Budget plan saved successfully', 201);
  } catch (err) {
    const mapped = mapServiceError(err);
    return sendError(res, mapped.message, null, mapped.statusCode);
  }
}

module.exports = {
  getBudgetPlanByMonth,
  upsertBudgetPlan
};
```

### What I Learned Here
- The controller never talks to the database directly — it always goes through the service
- `try/catch` is used so errors don't crash the server
- `mapServiceError()` translates internal errors into safe messages (never expose raw error to user)

## Step 4: Replace `src/routes/budgets.routes.js`

The routes file connects URL + HTTP method to a controller function. Validation middleware runs **before** the controller.

```javascript
const express = require('express');
const budgetsController = require('../controllers/budgets.controller');
const {
  validateRequest,
  validatePositiveIntRange,
  validatePositiveDecimal,
  validateRequiredString
} = require('../middleware/validate-request');

const router = express.Router();

// Validators for the POST /upsert body
const budgetBodyValidators = [
  validatePositiveIntRange('year', 2000, 2100),       // year must be 2000-2100
  validatePositiveIntRange('month', 1, 12),            // month must be 1-12
  validateRequiredString('categoryId', { maxLength: 50 }), // categoryId must exist and not be blank
  validatePositiveDecimal('plannedAmount')             // plannedAmount must be > 0
];

// GET /api/budgets?year=2025&month=6
router.get('/', budgetsController.getBudgetPlanByMonth);

// POST /api/budgets/upsert
// validateRequest runs first; if validation fails, controller is never called
router.post('/upsert', validateRequest(budgetBodyValidators), budgetsController.upsertBudgetPlan);

module.exports = router;
```

### What I Learned Here
- Validation middleware runs **before** the controller — invalid data never reaches business logic
- Routes are already registered in `src/routes/index.js` as `/api/budgets`, so `/upsert` becomes `POST /api/budgets/upsert`

## HTTP Status Code Reference

| Code | Meaning | When Used |
|------|---------|-----------|
| `200` | OK | GET success, or update success |
| `201` | Created | New record inserted |
| `400` | Bad Request | Validation failed (invalid input) |
| `404` | Not Found | Category or record does not exist |
| `409` | Conflict | Duplicate record or protected reference |
| `500` | Server Error | Unexpected database or code error |

## Key Takeaways

1. **Layered architecture**: Route → Middleware → Controller → Service → Database. Each layer has one job.
2. **Stored procedures handle upsert logic**: MySQL decides whether to insert or update — your JS code just passes parameters.
3. **Parameterized queries prevent SQL injection**: Always use `?` placeholders, never string concatenation.
4. **Never expose raw errors**: Use `mapServiceError()` to translate errors before sending to the client.
5. **Validation runs before the controller**: If input is invalid, the controller never executes.
